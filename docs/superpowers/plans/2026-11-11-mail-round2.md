## Global Constraints

- **Tests first** (TDD), in the existing test files and style. `ctest --test-dir app/build --output-on-failure` and `cd maild && cargo test` must be green before every commit.
  - Exception: `shellcheck_scripts`, which already fails on this machine because the mise shim has no shellcheck version.
- **Never run a window test binary without ctest's environment.** `TstUi::init()` and `zoomTo()` write `$XDG_CONFIG_HOME/omarchy-mail/window.json`, which would be the user's real file. Use `ctest --test-dir app/build -R '^tst_x$'`, or the `omt` helper from Part 2's header, which points every XDG directory into `app/build/test-home`.
- **Regenerating patches:** the user's git has `diff.mnemonicPrefix=true`. Always use `git -c diff.mnemonicPrefix=false diff …`. Before Part 3, qlitehtml is regenerated without its submodule and litehtml from its submodule; after Part 3, from `app/build/_deps/qlitehtml-src` and `app/build/_deps/litehtml-src`. After editing a patch, delete `app/build/_deps/qlitehtml-*` (and, after Part 3, `litehtml-*`) and rebuild: that proves the patch applies from scratch.
- **Commits:**
  - Style `app: …` / `maild: …` / `docs: …`, lowercase, no `Co-Authored-By` and no AI attribution.
  - Docs go in the same commit as the code: README.md, maild/PROTOCOL.md, and the spec when a decision changes.
  - Omarchy rules (`~/omarchy-dotfiles/docs/rules.md`, `changelog.md`) live in a separate repo, with their own commit.
- **No crutches** (definition in `~/.claude/CLAUDE.md`). A deliberate shortcut gets a `shortcut: <limit>, <when to upgrade>` comment.
- **Personal mail stays local.** No letter content in the repo, tests, commit messages or upstream texts. Tests use synthetic HTML.
- **Nothing outward without the user's yes:** no upstream PRs or Gerrit changes are sent (Part 3 Task 3.8 and Part 6 Task 6.10 only draft them). Pushing `main` to `origin` is the user's standing rule: push after each part merges with green tests.
- **During development** do not restart `maild` and do not start the installed window: a second launch talks to the user's open window. Installing (`./install.sh`) is the final step, once.

## Review Focus

1. **Letters arriving or relaying out under the cursor.** Images load right after a letter opens, and list reloads replace rows. The link cursor must stay on the same link (`tst_letter::link_indices_survive_images_arriving`, Task 5.4). The selection must survive (Task 6.9). Enter must never open an unringed link of another letter (`tst_app_actions::another_letter_drops_the_current_link`, Task 5.2).
2. **Hostile or very deep HTML** after the 12-table cap goes. The worker thread must not stall or overflow its stack on 240 nested tables (`deep_tables_lay_out`, Task 3.7). Hit testing must stay smooth on the heaviest receipt (manual check, Task 6.3).
3. **Keys typed into fields.** `a`/`g` (Ф/П) in the search field, the compose form and the mailboxes page must type, not open a picker. Esc must never close the window (`picker_keys`, `a_with_one_mailbox_does_nothing`, Task 1.8; the Esc chain, Task 1.6).
4. **Saving a mailbox when the trial login fails or the status churns.** `accounts.toml` and the keyring stay untouched (`account_update_failed_login_saves_nothing`, Task 2.4). Typed form fields survive `status` events (`settings_form_follows_the_cursor`, Task 2.6).
5. **Colour edge cases.** Hard gradient stops (`gradients_are_painted`, Task 4.3). Dark letters with links but no quotes (`links_take_the_accent`, Task 4.5). Limited-quirks doctypes in fix B (`cell_height_holds_its_row` xhtml = 60, Task 3.2).
